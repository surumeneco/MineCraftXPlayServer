# CoreProtect運用設定

## 記録対象

`config.yml` に全ワールド共通の記録項目を定義し、イベント記録を既定で無効化する。`world.yml`、`world_nether.yml`、`world_the_end.yml` でのみ、各ログ項目を既存の記録方針に従って有効化する。ワールド名はMinecraftのワールドフォルダ名と一致させる。3ファイル以外のワールドは共通の記録無効設定を継承する。

## Git管理とデプロイ

`config.yml`、ワールド別設定、`language.yml` およびJARは共有設定としてGit管理する。`database.db`、DuckDB/SQLiteのDB・ジャーナル、ローカルライセンス・言語状態はGitで追跡しない。DBはVPS側の永続データであり、別途バックアップする。

**初回デプロイ時の注意:** 旧リポジトリでは `plugins/CoreProtect/database.db` が追跡されていた。今回の変更はGitからそのファイルを削除するため、Git更新時にVPSの実データまで削除される可能性がある。必ずMinecraftを停止し、`plugins/CoreProtect/` 配下のDB・ローカル状態をリポジトリ外へ退避してから更新する。更新後、バックアップしたDBを元の場所へ復元してからサーバーを起動する。DBがない状態で起動すると空のDBが作られる可能性がある。

適用後は `/co reload` または再起動後、3ワールドと除外ワールドそれぞれで新しいブロック設置・破壊操作の記録有無を確認する。既存DB内の履歴は設定変更だけでは削除されない。
